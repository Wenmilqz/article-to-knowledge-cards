# Make Knowledge Cards

## 目标

把一份文章或本地 Markdown/TXT 文件压缩成一组（默认 5~8 张）知识卡片。每张卡片承载一个独立、真实、重要的知识点，便于用户复习、背诵或分享。

## 输入

- 粘贴在对话里的文章正文；或
- 本地 Markdown（.md）或 TXT（.txt）文件路径——先用 Read 完整读取全文，不以摘要或印象代替。

**不支持的输入**（直接说明原因并拒绝，不尝试处理）：
- 网页 URL（本 Skill 不做网页抓取）；
- PDF 文件；
- 导出 Anki 卡片的需求；
- 图形界面需求。

## 工作流程

1. **通读全文**：完整读取输入，不要跳过格式复杂或冗长的部分。
2. **识别知识点**：按“对读者的知识价值”排序，挑出真正重要、可独立成立的知识点，而不是按原文出现顺序抄段。
3. **去重**：同一知识点在文中反复出现时，只保留一次。
4. **逐点成卡**：每个知识点做成一张卡片，遵守“一张卡片只讲一个知识点”。
5. **裁剪数量**：
   - 默认 5~8 张；
   - 若有效知识点不足 5 个，就少做几张（3 张、2 张都可以），绝不为了凑到 5 张而拆分知识点或编造内容；
   - 若知识点超过 8 个，只保留最重要的 8 个。
6. **输出**：按下面的卡片格式呈现所有卡片。

## 卡片格式

每张卡片固定四部分，严格按此顺序，卡片之间空一行分隔：

```
卡片 N：〈一句话标题〉

【核心知识】一句话，直接陈述该知识点是什么。

【简明解释】2~4 句，用更通俗的话把核心知识讲清楚。

【例子 / 自测问题】给一个来自原文的例子，或一个能检验是否掌握的自测问题（二者取其一）。
```

## 质量规则（必须遵守）

- **只使用原文信息**：核心知识、解释、例子都必须来自输入文本。不得补充、推测或编造原文没有的事实、数字或结论；用自己的话重述时，只能基于原文已表达的内容。
- **不强行凑数**：信息不足时，卡片可以少于 5 张，并可在开头用一句话说明“原文信息有限，仅整理出 N 张”。
- **一张卡片一个知识点**：不要把两个独立知识点塞进同一张卡片，也不要为凑数量把一个知识点拆成多张。
- **标题要具体**：标题应能独立看出该卡片讲什么，避免“第一章要点”“总结”这类空泛标题。
- **忠实原文**：例子若引述原文数字或结论，必须与原文一致，不得改写数值或偷换含义。
- **叙事/文学文本**：只提取文中明确陈述的事实；不推断、不添加原文未明说的寓意、主题或结论。若几乎没有可成卡的知识点，就少做几张并在开头说明。

## 交付

- 默认：直接在回复中输出所有卡片。
- 若用户要求保存为文件：写成一个 Markdown 文件，每张卡片以 `## 卡片 N：标题` 开头，放在用户指定或合理的位置。
